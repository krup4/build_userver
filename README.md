# Анализ времени сборки userver

Нужен запущенный Docker. После распаковки откройте этот каталог в терминале:

```bash
./run.sh
```

Всего два скрипта:

- `run.sh` запускает точный Docker-образ из задания с лимитами 4 CPU / 8 GiB.
- `measure.sh` создаёт fresh service, собирает CBA 1.6.0, делает замеры,
  переносит include `cluster.hpp` из `.hpp` в `.cpp` и повторяет замеры.

Сырой вывод Clang Build Analyzer:
- `baseline.txt` - до оптимизации
- `optimized.txt` - после оптимизации

Используются Clang 14, Release, `-j4`, time-trace ON и ccache OFF.
Для каждой версии выполняются одна чистая сборка для CBA и ещё три чистые сборки
для замера времени. Установка инструментов и настройка CMake в замеры не входят.
Кеш файлов ОС не очищается. Базы данных и тесты не запускаются.

После успешного запуска в `results/`:

| Файл | Содержимое |
| --- | --- |
| `baseline.txt`, `optimized.txt` | Сырые отчёты ClangBuildAnalyzer |
| `baseline.bin`, `optimized.bin` | Бинарные данные ClangBuildAnalyzer |
| `baseline-time-1.txt` … `baseline-time-3.txt` | Три исходных замера: real/user/sys |
| `optimized-time-1.txt` … `optimized-time-3.txt` | Три замера после оптимизации |
| `summary.txt` | Медианы wall-clock времени в секундах |
| `environment.txt` | ОС, архитектура и версии инструментов |
| `*.log` | Вывод каждой сборки, в том числе ошибки |

Повторный запуск начинает эксперимент в новом контейнере и перезаписывает результаты.
Не запускайте два эксперимента одновременно из одного каталога.
При ошибке скрипт останавливается; `summary.txt` появляется только после всех сборок.
